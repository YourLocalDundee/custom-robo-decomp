Custom Robo scenes: stages, projectile / blast effects, particles

Everything known about the game's scene_data files (stages, the effects of guns, bombs, pods, charge attacks and legs, the common effects, story objects) and the stage collision, in one page for modders and tool writers. Each fact is read from the game's code (function addresses given) or counted over every file on the disc (US, GXCE01); anything not verified says so. Deeper pages: stage_tables.md (every stage, its record, the collision table), formats/containers.md (the archives), MODDING.md ("Stages", "Effects"), IMPORT_EXPORT_GUIDE.md (vertices, textures, the import rules).

2The HSD .dat file (verified: HSDLib and our reader agree on every file)

All effect, stage and object models are standard sysdolphin .dat files, as in Super Smash Bros. Melee (HSDLib / HSDRawViewer read and write them). Big-endian.

OffsetWhat
0x00u32 file size
0x04u32 data block size D
0x08u32 relocation count
0x0Cu32 root count
0x10u32 reference (extern) count
0x20the data block (D bytes); every pointer in it is an offset from 0x20
0x20 + Drelocation table: one u32 per pointer word (its data offset)
thenroots: (u32 data offset, u32 name offset) each
thenreferences: the same, for symbols resolved from another file
thenthe name strings (offsets from here)

Every scene file of this game has one root, scene_data (the game asks for it by name, HSD_ArchiveGetPublicAddress(archive, "scene_data")).

3scene_data: the scene object (HSDLib HSD_SOBJ; verified in the game's loaders)

OffsetWhatUsed by the game
+0x00null-terminated array of model pointers (JOBJDesc)always
+0x04null-terminated array of camera descsnever (the battle camera is the game's own)
+0x08null-terminated array of lights ({LightDesc, animation list})stages only (HSD_LObjLoadDesc, at most 10)
+0x0Cfog ({FogDesc, AObj})stages only (HSD_FogLoadDesc; its colour becomes the clear colour)

A model (JOBJDesc, 0x10 bytes): root joint, then three null-terminated arrays: joint animations (AnimJoint trees), material animations (MatAnimJoint trees), shape animations. The game loads the root with HSD_JObjLoadJoint and attaches the first animation of each array (HSD_JObjAddAnimAll).

The structures below a joint are standard: Joint (0x40: name, flags, child, next, DObj list or particle joint, rotation, scale, translation, inverse bind matrix, constraints), DObj (mesh: next, MObj, PObj list), MObj (material: render mode, TObj list, colours, pixel engine), TObj (texture: image, palette, wrap, scale, filtering, a texture matrix), PObj (vertex attributes and display list; rigid, envelope or shape animation). Details for modellers: IMPORT_EXPORT_GUIDE.md sections 3-4.

Animations (standard HSD): an AObj holds flags, end frame and a list of FObjs, one per animated channel; an FObj is a compressed keyframe stream (key opcodes CON / LIN / SPL0 / SPL / SLP / KEY, values quantised by its format byte). Channel types seen in this game:

KindChannels
jointrotation x / y / z, translation x / y / z, scale x / y / z, 40 = PTCL: fire a particle generator
materialambient / diffuse / specular r, g, b, alpha
textureimage swap (timg), translation u / v, scale u / v, rotation, blend

A PTCL key carries a 24-bit code (bytes 1-3 of the key, little-endian): bank = bits 0-5, generator = bits 6-23, a global number (bank b's generators are numbered from b x 1000). Gun 0's hit emitter fires 6107 and 6110 (bank 6, generators 107 and 110). The game registers the particle callbacks at boot (cr_Particle_InitCallbacks 0x80075CA8: HSD_JObjSetSPtclCallback, HSD_JObjSetDPtclCallback, HSD_JObjSetPtclTargetCallback).

5Stages (verified: fn_80072064, fn_80072B90, fn_80070170, fn_80072A58)

The model entry (2s) is one scene. The stage build loads every model into a 0x13C-byte record (lbl_8037569C + 0xB8 + n x 0x13C), at most 20, attaches its first animations (models with any animation get flag 0x10000000 and are set to frame 0), loads the lights (at most 10; the first with type bits 1 also gets a 600 x 440 shadow) and the fog. It hangs if a root joint of models 1 and up has more than 21 DObjs. The camera desc is never read. The stage record's +0x88 (main.dol, per stage) is the model count the game uses after loading.

The collision entry (2s + 1) (verified by a byte-identical rebuild of all 39 entries of this format; entry 015, the RPG test stage, has another layout):

WhereWhat
+0x00u32 N: groups (group n belongs to scene model n)
+0x04offset of N group-header offsets
+0x08offset of N quad-array offsets
+0x0Coffset of section C (the waypoint records), or 0
group header (0x20)bounding sphere x, y, z, r; u32 quad count; u32 model flags; 2 x u32 0
quad (0x44)4 corners (12 floats), unit normal (3 floats), plane d (n . p + d = 0), u32 attribute
layout0x10 header, the two tables, zero padding to 0x10; per group its header and quads, padded to 0x10; section C
section C0x284-byte records to the end: a waypoint graph for the computer players (likely; fn_8006D4F8 links records with a clear line of sight); Impact Craters (stage 0x18) copies 48 of them

Rules read from the retail data (all 3,069 quads):

  • normal = normalise((c1 - c0) x (c2 - c0)), d = -n . c0, and the normal points to where a robo stands: arena walls face in, obstacles face out (an obstacle box has 4 sides and a top, no bottom).
  • The sphere is the corners' box centre with the farthest corner as radius (391 of 413 groups; the other 22 are a little smaller than their corners).
  • Attributes (surface kinds): 0 mostly; 8, 24, 25-28, 256, 512, 1024-2048, 1280, 5376, 197376 seen; not mapped.

Model flags (the group header word, copied to the model record +0xF8):

BitsMeaning (from the code)
0-2 (non-zero)breakable model: hit points = {1000, 100, 150, 200, 250, 300, 350, 400}[flags & 7] (0x802176C8); damage adds up at record +0x104; past the hit points the game fires effect / sound 0x3000F and plays the model's break animation to its end; while it is hit, its first two textures' blending flash for 4 frames
3-4, or 0x20moving collision: the group is copied each frame through the model's matrix (fn_800730F8, through lbl_8044EA50); at most 20 such groups, each at most 100 quads (the copies' buffers 0x803754BC / 0x8035417C)

Some stages have hard-coded extras in fn_80072B90 (stage ids 2, 3, 8, 9 (models 6 and 7) and 0xC: animations set to frame 0 on model 0). Spawn points and the battle camera are not in these files (not located yet).

6Effects: shots, blasts, charge attacks, legs (verified: fn_80075950, fn_8007571C, fn_80078000)

Each entry of gun / bomb / pod / attack_effect is a small wrapper: u32 count (2), count + 1 offsets (the last is the end), zero padding to 0x20, then two .dat files (each padded to 0x20). leg_effect entries are one .dat.

Which model goes where (the callers' constants): gun piece 0 models 0 and 1 per shot (shot record +0x310 / +0x314), model 2 per gun (+0x2DC); gun piece 1 models 0 and 1 per shot (+0x350 / +0x354, the hit); charge attack piece 0 model 0 at robo +0x1DCC and piece 1 model 0 at +0x1DD0; leg models 0, 1 (four copies) and 2 at robo +0x333C0 .. +0x333D4. Each instance is a separate joint tree with its own animation (HSD_JObjLoadJoint + HSD_JObjAddAnimAll per spawn). The effect files' cameras, lights and fog are never read.

Common effects (efc_common.dbn): a u32 count (4) + offsets; 4 .dat files, scene_data each, at 0x80379970[0..3]: [0] robo +0x1E08 and [3] robo +0x333D8 (cr_BattleRobo_InitFromLoadout), [2] the gun updater (fn_80044174), [1] one model per index (fn_80089550).

Adding collision to new geometry (for example a pillar added with the model loop): export the collision, add the obstacle's faces to group_0 (or the group of the model it sits on) in Blender with outward-facing normals (4 sides and a top), export the OBJ again (keep the axes) and import it. Checked: Basic Arena with a 1.2 x 1.2 x 2.6 box gets 5 new quads in group 0 with the expected normals, every other byte unchanged.
