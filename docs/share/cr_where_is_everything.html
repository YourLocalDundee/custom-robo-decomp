GameCube · GXCE01 · Custom Robo

Where everything is: animations, stages, effects (the short version)

The plain-language map. For the byte-level details see ANIMATION_GUIDE.md (animations) and SCENE_GUIDE.md (stages, effects, particles). All file names are under the disc's files/ folder (Custom Robo extracted/files/ after the one-time build).

1Robo animations (walk, jump, shoot, victory, charge attack ...)

Stored in: logo_read_us.dbn, entry 8. Not motion.DBN (the game never reads that file).

What it is: a list of motions, each with a number (its ID, 0..1094). A motion is a set of curves for an invisible stick figure: where the hips, hands, feet and head should be, and how 16 joints turn. It does not store the robo's bones. Every frame the game bends each robo's own arms and legs to reach those points, so one motion works for every robo.

How a robo picks its animation:

1. Each body has a list of 38 "slots" in main.dol (stance, walk, run, jump, gun, bomb, pod, falls, get-up, lose, victory 1 and 2, charge attack, ...). Each slot holds one motion ID. 2. What the robo is doing (its action: moving, shooting, falling, winning ...) picks the slot every frame. 3. When the slot's motion is a different one from what is playing, the game switches to it and blends from the old pose to the new one over 16 frames, so moves flow into each other. 4. Most motions run at 30 frames a second. Victory, lose, charge attack and get-up do not: the game sets their frame from its own timers (victory waits, then plays over 140 game frames; the charge attack plays its 60 frames as three 20-frame parts, each stretched to that phase's duration).

Find it:

python -I tools/anim.py slots --body 20                  # Breaker's 38 slots: motion name, ID, length
python -I tools/anim.py export --body 20 --slot victory2 # -> build/anim/<name>.glb, open in Blender
python -I tools/battle_motions.py --tsv                   # every body x slot

3Stages

A stage with id s is two entries of bg_data.BIN:

EntryWhat
2sthe look: up to 20 models (each can carry its own looping animation), lights, fog
2s + 1the walls and floors robos collide with: one group of flat four-cornered faces per model, plus a waypoint list (most likely for computer players)

A model's collision group also says whether that model is breakable (and how many hit points: 100 to 400) or moving (its collision follows its animation).

Find it:

python -I tools/scene.py list stages            # id, name, entries, how many models / collision groups
python -I tools/scene.py info stage 0           # every model, its animation (length, what it moves), lights, fog, collision
python -I tools/scene.py export stage 0         # -> build/scene/stage_000/: one .glb per model + the collision .obj
python -I tools/stage_collision.py info 0       # collision groups, breakable / moving flags

4Shots, blasts, charge attacks (effects)

Each gun, bomb and pod has its own effect entry (same number as the part); charge attacks are by body number. Every entry holds two model files:

PieceWhat
0what flies: the shot or blast meshes, one copy per shot
1what happens on hit: particle emitters (guns) or the explosion meshes (bombs, pods, charge attacks)

Find it:

python -I tools/scene.py list effects --kind gun   # per gun: models, meshes, particle tracks of both pieces
python -I tools/scene.py info effect gun 12        # both pieces of gun 12's effect
python -I tools/scene.py export effect bomb 3      # -> build/scene/bomb_effect_003/

Ready-made exports of everything are in models_export/ (made by the one-time build): models_export/chara/, bg_data/, gun_effect/, ... one folder per entry.
